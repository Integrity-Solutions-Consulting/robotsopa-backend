# PostgreSQL de ensayo

Esta configuración es independiente y **no es un backend de producción**: la aplicación todavía utiliza SQLite y JSON. No apunte la aplicación a esta base esperando una migración funcional. La importación conserva una instantánea de las tablas y el JSON en una tabla de ensayo; no crea usuarios de aplicación ni conecta al worker. No hay conversión de datos de aplicación ni validación de equivalencia todavía.

En un entorno aislado, cree la red externa y despliegue `deploy/postgres/compose.yml` con un nombre de proyecto estable y las variables de `.env.example` definidas como secretos en Dokploy. No publique el puerto 5432. El volumen `pgdata` contiene la base y debe incluirse en los respaldos. La contraseña de ejemplo no es una credencial válida para producción. Cambiar `POSTGRES_PASSWORD` después de inicializar el volumen no cambia automáticamente la contraseña existente.

Conecte `psql` al servicio privado mediante sus variables `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER` y una entrada en `.pgpass` con permisos restringidos. Sobre una base de ensayo vacía ejecute `psql -X -v ON_ERROR_STOP=1 -f deploy/postgres/migrations/001_staging.sql`. Detenga API, worker y agente en el origen y copie sus datos como conjunto. Luego ejecute `python scripts/import_legacy_staging.py --sqlite /ruta/copia/panel.db --state /ruta/copia/state.json`. Cada ejecución crea una nueva instantánea: no sustituye datos existentes. La instantánea contiene hashes y datos personales; proteja el acceso y el respaldo. Conserve los originales, incluidas claves y archivos. La instantánea no contiene descargas ni claves.

Para respaldar la base de ensayo desde un entorno que tenga `pg_dump` y credenciales configuradas, ejecute `pg_dump --format=custom --file=backup.dump` sin publicar la contraseña en la línea de comandos. Guarde el archivo cifrado fuera del host y restrinja sus permisos. Para ensayar restauración, cree una base nueva y aislada, configure `PGDATABASE` con su nombre y ejecute `pg_restore --exit-on-error --no-owner --dbname="$PGDATABASE" backup.dump`; verifique los datos. Nunca restaure encima de una base activa. Respalde por separado los archivos y claves de la instalación original. No se ha probado aún la restauración.
